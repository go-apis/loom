# Goal — loom has CI, and a merge makes a tag

Mesh goal `loom-release-path`, running.

## Statement

G0, loom's half. loom has no workflows: add CI running go test ./... with a Postgres service container, and tag on merge — every merge to main gets the next minor tag unless it carries a patch label. The bump PRs on consumers are runsheet's half, a separate goal. The brief is runsheet/runsheet specs/proposal-loom-for-adr-001.md (Prologue, project runsheet), section 3. loom has ten consumers (runsheet, wardroom, latchkey, grapevine, optrader, ten99 on v0.49.0; tripline, purser, foghorn on v0.46.0): every change is backward compatible or ships behind an opt-in, and the consumers' adoption is their own goals, not this one's.

## Acceptance

A PR's CI runs the full suite against Postgres and blocks the merge when red; merging a one-line PR produces the next tag without a person; a patch-labelled merge produces a patch tag.

PR [#32](https://github.com/go-apis/loom/pull/32) is open and green. ## What I did The review was right that the workflow file needed nothing — the missing piece was the GitHub-side evidence. Opening the PR produced it, and the first real run immediately found something local runs could not: **CI went red, with all seven Postgres-backed e2e tests timing out.** Root cause: a started loom client parks two connections for its lifetime — one on `LISTEN` (`stream.go:78`), one holding the process lease (`election.go:57`). The e2e tests run `orders` and `billing` off a single pool, so four connections are parked before a query is issued. `pgxpool` sizes a pool at `max(NumCPU, 4)` — exactly 4 on a GitHub runner — so the pool was empty and every `Load`/`Dispatch` blocked until the test's context expired. On the 18-core box here the same pool gets 18 and the suite passes in 22s, which is why attempt 1's local verification looked clean. Two changes beyond the workflow (`2ea8bdf`): - `internal/e2e/e2e_test.go` — `testDB` now pins `cfg.MaxConns = 20`, sizing the pool for what the harness runs rather than the host's core count. `LOOM_TEST_PG` is still unset and the default DSN is untouched. - `README.md` — wrote the connection budget down next to the lease paragraph. It's a real constraint for the ten consumers, not just a test detail.
